# 智选 Agent｜Coze MVP 测试报告

## 结论

截至本仓库当前版本，**A–D 四个固定用例已完成两层验证：本地等价规则 4/4 通过，Coze `v0.2.0` 原生试运行 4/4 通过**。当前 `v0.2.1` 仅替换商品名称，静态合规扫描通过；平台资源点耗尽后未重复调用 LLM。

本结论不是人工阅读示例后填写的“通过”。实际运行 `python3 scripts/validate_bundle.py` 后，271 项断言全部通过；另运行 `python3 -m unittest discover -s tests -v`，5 项回归测试全部通过。Coze 项目 `7679015075092578350` 又独立执行四次原生试运行，并保存了脱敏截图。两层结果分开陈述，不把本地复算冒充成平台输出。

## 复现命令

在仓库根目录运行：

```bash
python3 scripts/validate_bundle.py
python3 -m unittest discover -s tests -v
```

预期第一条命令返回退出码 `0`，并显示 `PASS: 271 项断言全部通过`；第二条命令显示 `Ran 5 tests` 与 `OK`。验证器仅使用 Python 标准库，不需要安装依赖。任何 JSON 解析失败、硬过滤越界、分数/预算差额不一致、关键 trace 来源错误、平台证据缺失或把未完成的 `v0.2.1` 复跑标成通过，都会使验证失败。

## 关键断言

### A：推荐排序

- 硬过滤后候选 4 条，`NB-005` 因价格 8999 元高于预算而被排除；
- 第一名 `NB-001` 的需求匹配为 100，预算匹配为 87.49，总分为 89.98；
- 三条推荐的 `budget_gap` 分别为 1001、1、2201，均等于 `8000 - price`；
- 每条推荐理由至少包含一个商品库中的限制字段。

### B：缺失信息追问

- 能识别 `头戴耳机` 和 `降噪`；
- 不把用户没有提供的预算与使用场景补齐；
- `missing_fields` 保留两个缺失字段，但按优先级只询问预算；
- `retrieval_executed = false`，避免在关键约束不足时提前推荐。

### C：无结果兜底

- 笔记本电脑品类中有库存的最低价格为 5799 元；
- `100` 元预算下硬过滤候选数为 0；
- 预算提升建议为 `5799 - 100 = 5699` 元；
- 推荐数组为空，未返回商品库之外的名称。

### D：推荐排序

- 硬过滤后候选 4 条，`PH-005` 因价格 6999 元高于预算而被排除；
- Top 3 的总分依次为 92.67、90.26、85.50；
- 三条结果均明确覆盖“拍照”和“通勤”；
- 价格、预算余量与商品库一致。

## Coze 平台验收步骤

1. 使用 15 条完全合成商品与 `rule_v1` 公式搭建节点；
2. 分别运行 A–D，不手工编辑节点输出；
3. 核对 `status`、Top 3、追问、空推荐数组与兜底动作；
4. 发现 `use_case` 曾被错误设为可选后恢复三字段必填，并为“高性能”增加确定性归一化；
5. 将所有现实或近似现实型号替换为原创中文名称；
6. 重新运行 A–D，四项通过后保存脱敏证据；
7. 记录当前项目视图无原生单文件导出入口，不把等价 JSON 改称原生导出。

`v0.2.1` 名称修正后，静态扫描确认 15 个 `name` 不含真实或近似现实品牌/系列关键词；尝试重跑时平台返回资源点不足。因为 ID、价格、库存、评分、销量、场景、优缺点、代码、路由与分数均未修改，预期状态和排名不变；但没有新的原生调用就不标记为 `v0.2.1` 实测通过。

## 两层验证为什么允许商品 ID 不同

公开本地包和 Coze 原型使用各自版本化的合成目录。前者用于让访问者离线重算硬过滤、分数、预算差额与 trace；后者用于证明 Coze 中的参数抽取、分支编排、LLM 理由节点和兜底真实可运行。验收对齐的是输入契约、三种状态、必填字段、硬过滤、`rule_v1` 与事实边界，不把本地商品 ID 或分数冒充为平台原生输出。

## 已知测试空白

- 多轮会话中补充预算后的状态合并；
- 非法预算、空输入、超长文本与中英混合表达；
- 同分商品的稳定排序；
- 大模型理由节点的格式漂移与内容安全；
- 商品库规模扩大后的延迟与 token 成本。

这些项目属于后续质量保障范围，不影响本次核心流程的本地一致性结论。
